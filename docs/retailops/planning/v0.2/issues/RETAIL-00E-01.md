# RETAIL-00E-01 | 单店经营开源业务研究

状态：PROPOSED（未创建远程 Issue，未认领）｜阶段：P｜责任角色：领域｜类型：调查/准备，仅文档为默认

## 1. 背景与目标
旧版业务仍是比价/调拨，需重新建模。本任务独立交付其职责，不承担下游模块实现。

## 2. 范围与明确不做
只研究 RetailBench 与 Grocery Optimizer、Inventra 的业务/仿真/审批设计；不移植运行时。不得修改未声明的模块、依赖版本、通用安全策略、既有断言；不连接真实商超写接口。调查任务不提前实现业务源码。

## 3. 输入
V0.2 场景草案及三个候选 GitHub 仓库。实际启动时冻结上游 PR/commit、契约版本及证据路径；输入缺失或变更则停止并报告。

## 4. 输出
引用固定版本的领域研究报告、候选模型及复用边界。

## 5. 环境与前置条件
公开仓库；检查许可证，无法确认则只参考思路。基线 WSL2 Ubuntu 24.04 / Node 24 / 原锁文件；执行前检查 git status、HEAD、用户授权、依赖验收。涉及真实模型/副作用只在批准的隔离实例执行。

## 6. 依赖与上下游
- 硬依赖：无新增任务硬依赖；仍需总体计划获批。
- 直接下游：RETAIL-00C、RETAIL-03。
- 依赖仅在对应契约/证据通过且 PR 已合并（或经批准的只读调查输入固定）后满足；BLOCKED、NOT_RUN 不视为满足。静态调查可记录负结论，但不得因此放行依赖实际运行能力的任务。

## 7. 实施步骤（初始）
1. 固定 repo/commit/license。节点验收：来源清单。
2. 追踪单店事件及批次/策略。节点验收：模型映射。
3. 分析风控和评估。节点验收：可用/不可用矩阵。

每一步完成后执行总体计划的三方语义对齐（PRD/总体计划、Issue/Plan、节点标准），偏差修复并复测；不得跨过未通过节点。详见 `plans/RETAIL-00E-01-PLAN.md`。

## 8. 测试用例
- T01：复核路径、许可证与关键业务例；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- T02：至少一条手算库存守恒和损耗场景；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- 文档/工程回归：`git diff --check`、`npm run docs:check`；涉及源码时执行实际存在的类型检查及相关定向测试，记录命令、退出码和基线失败。测试位置和准确命令在认领时依据实际源码细化，不假定当前存在零售测试文件。
