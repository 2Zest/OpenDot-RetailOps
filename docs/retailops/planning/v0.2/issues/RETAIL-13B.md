# RETAIL-13B | 补货决策执行闭环

状态：PROPOSED（未创建远程 Issue，未认领）｜阶段：V1｜责任角色：业务｜类型：工程/业务增量

## 1. 背景与目标
复用审批执行基础扩展单店补货。本任务独立交付其职责，不承担下游模块实现。

## 2. 范围与明确不做
只增加补货 action 适配及模拟采购到货；复用审批/风控，不造第二套状态机。不得修改未声明的模块、依赖版本、通用安全策略、既有断言；不连接真实商超写接口。调查任务不提前实现业务源码。

## 3. 输入
13A、已有审批/执行/恢复接口。实际启动时冻结上游 PR/commit、契约版本及证据路径；输入缺失或变更则停止并报告。

## 4. 输出
补货工具/草案/action adapter、端到端收据。

## 5. 环境与前置条件
隔离仿真；模拟供应商，不真实下单。基线 WSL2 Ubuntu 24.04 / Node 24 / 原锁文件；执行前检查 git status、HEAD、用户授权、依赖验收。涉及真实模型/副作用只在批准的隔离实例执行。

## 6. 依赖与上下游
- 硬依赖：RETAIL-13A、RETAIL-18C、RETAIL-11、RETAIL-12。
- 直接下游：RETAIL-19、RETAIL-20A。
- 依赖仅在对应契约/证据通过且 PR 已合并（或经批准的只读调查输入固定）后满足；BLOCKED、NOT_RUN 不视为满足。静态调查可记录负结论，但不得因此放行依赖实际运行能力的任务。

## 7. 实施步骤（初始）
1. 扩展动作 schema。节点验收：兼容迁移。
2. 通过现有链路批准模拟采购。节点验收：回执。
3. 模拟到货与取消。节点验收：库存守恒。

每一步完成后执行总体计划的三方语义对齐（PRD/总体计划、Issue/Plan、节点标准），偏差修复并复测；不得跨过未通过节点。详见 `plans/RETAIL-13B-PLAN.md`。

## 8. 测试用例
- T01：拒绝、重复采购、供应商不可用、部分到货、重启；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- 文档/工程回归：`git diff --check`、`npm run docs:check`；涉及源码时执行实际存在的类型检查及相关定向测试，记录命令、退出码和基线失败。测试位置和准确命令在认领时依据实际源码细化，不假定当前存在零售测试文件。

## 9. 验收标准
同一审批机制完整工作；不重复入库或采购；旧定价回归通过。所有必需节点 PASS、实际证据可复核、未验证与阻塞如实标明、无越界修改，Review 通过并合并才 DONE；调查结论通过不等于被调查能力运行通过。
