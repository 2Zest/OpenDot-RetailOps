## 1. 产品目标与用户

为单店商超店长提供有证据、可复核、受政策约束的经营决策支持。V0 只验证一个生鲜 SKU、一个临期批次的损耗治理闭环：整理输入及来源、测算受限的折价/处置方案、由独立风控检查、由店长审批，并只在隔离的仿真业务状态中执行和反馈。

主要角色：

- **店长/业务审批人**：确认业务目标、政策参数及决策草案；对业务动作作出明确批准或拒绝。
- **经营分析 Agent**：读取允许的数据并提出含依据和不确定性的草案；不得自行批准或执行。
- **独立风控角色**：按只读业务政策审查风险并给出结构化结果；与分析角色、审批人和执行服务分离。
- **受控仿真服务**：在确定性规则与批准范围内修改仿真状态，不连接真实 POS、支付、采购或供应商写端。
- **审计/评估人员**：复核输入快照、政策版本、审批、模拟执行与结果的关联。

## 2. 范围

### V0：单 SKU、单批次损耗治理

- 一家门店、一个待选 SKU、一个待选临期批次；具体商品、单位、保质期窗口和参数待业务审批。
- 以可追溯的公开历史观察和明确标记的仿真状态作为输入。公开数据不能伪装为目标门店的真实库存、批次、成本或实际销售件数。
- 形成只读分析结果和限界的决策草案；安全/质量硬规则优先于收益目标。
- 分析、独立风控、店长业务审批、受控仿真执行、状态核对与结果反馈形成可追溯闭环。
- 对重复请求、中断恢复、取消、权限拒绝和执行状态不确定建立明确合同；真实运行验收仍由对应下游 Runtime Issue 完成。

### V1：后续扩展，不属于 V0 承诺

在 V0 合同及运行验收完成后，才依据数据覆盖与用户决策扩展多 SKU、单店多批次、线上预占/完成/取消与线下销售共享库存、补货及多 SKU 经营异常诊断。20–50 SKU 是待验证的候选规模，不是已确定门槛。

## 3. 非目标与硬边界

- 不实现业务代码、数据库迁移、API、MCP 工具或 Agent 工具；这些属于下游 Issue。
- 不接真实 POS、支付、采购、称重硬件、供应商、商城或真实库存写接口。
- 不做竞品比价、叠券、大促、跨门店调拨、区域仓、消费者推荐、复杂物流或自动采购。
- 不允许 Agent 绕过业务审批、工具注册、Grant、权限策略或安全硬规则。
- 不因开源项目存在某种能力而声称 RetailOps 已具备该能力；不以静态调用链或 fixture 测试替代真实运行验收。
- #7 独立安全验证环境保持 Open/BLOCKED。该阻塞及 #16 Durable、#17 MCP、#18 Handoff 等运行门槛均不由本 PRD 解除。

## 4. 业务与领域需求（审批编号）

下列 `PRD-Rxx` 为本草案的追溯编号，并非既有已实现功能。

| ID | 需求 | 验收语义 |
|---|---|---|
| PRD-R01 | 单店经营上下文 | 每项草案明确门店、业务时段、目标 SKU 与来源快照；V0 一次只含一个 SKU。 |
| PRD-R02 | SKU/批次与质量边界 | 批次记录单位、数量来源、生产/到期信息和质量状态；具体字段待决策。过期或质量异常商品不得出售或通过折价绕过。 |
| PRD-R03 | 库存守恒 | 以 `on_hand`、`reserved`、`available = on_hand - reserved` 描述共享库存；任何仿真转换不可造成负可用库存。V0 可不实现 V1 订单流，但不得产生与该合同冲突的状态。 |
| PRD-R04 | 订单事件语义 | 目标合同定义收货、销售、预占、释放/取消、完成、损耗与盘点调整；取消只释放预占，完成只扣减一次。线上预占/完成/取消的功能交付属于 V1，V0 仅冻结与损耗闭环有关的必要语义。 |
| PRD-R05 | 数据来源与可解释性 | 每个字段带来源层与快照标识：`PUBLIC_HISTORICAL`、`DERIVED`、`SIMULATED` 或 `LIVE_DEVICE`。当前调查没有 LIVE_DEVICE 集成证据。 |
| PRD-R06 | 受限建议 | 输出候选动作、所依赖事实、假设、限制、预期影响区间和不确定性；不得声称仿真折价响应代表真实因果。 |
| PRD-R07 | 职责分离与业务审批 | 分析、独立风控、业务审批、受控执行各自可区分；风控意见不能代替店长批准，工具调用批准也不能代替业务审批。 |
| PRD-R08 | 冻结与再验证 | 待批准草案绑定输入快照、政策版本、目标/参数及发起主体；审批或执行前重新校验草案摘要、授权和业务前置条件。 |
| PRD-R09 | 幂等、恢复与不确定状态 | 重试不得重复产生副作用；副作用结果 uncertain 时须先对账/查询并确定真实状态，禁止盲目重试。失败或 uncertain 不算完成。 |
| PRD-R10 | 审计与反馈 | 记录输入来源、计算/模型版本、政策、风控结果、批准/拒绝、仿真动作及反馈数据；真实业务效果与模拟结果分开报告。 |

## 5. 数据解释合同

- **PUBLIC_HISTORICAL**：RETAIL-00E-02 研究的 FreshRetailNet 公开历史观察，许可证及样本证据见调查报告。已核实 `store_id=0` 的 74 个编码 `product_id` 在 97 天共同窗口有记录；该编码门店不等于可识别的真实商店，行数/覆盖也不等于真实业务覆盖。
- **DERIVED**：由有版本的公开/仿真输入按确定规则计算的特征、候选需求或统计量。保存派生方法版本与父输入引用。
- **SIMULATED**：以固定场景参数和种子生成的库存、批次、价格响应、订单、损耗或执行效果。必须醒目标记为模拟。
- **LIVE_DEVICE**：真实门店/POS/传感器设备数据层；当前没有相应接入证据，不得在数据模型、界面或报告中伪称已接入。

公开数据中的规范化销量/活动/折扣/缺货等字段不得转换成未观测到的件数、实际成本、真实售价、批次、现存库存、真实收入或毛利。缺货期间观察到的销量是受库存截断的观测，不能当作完整需求。价格响应属于仿真假设或待验证估计，不是因果结论。

## 6. 候选业务指标（公式待批准）

草案建议分别呈现模拟售出量、模拟报损量、剩余量、模拟收入/成本/毛利估计、折价幅度与规则命中情况；不得把互不等价的公开归一化数据与仿真金额相加。分母、成本来源、单位、舍入、折价弹性、无动作基准和时间窗均列入 `DECISIONS-PENDING.md`，在审批前不冻结公式，也不以 KPI 达标宣称产品有效。

## 7. 用户旅程与状态

1. 数据快照及模拟库存输入被校验并标注来源。
2. 分析角色生成不可执行的决策草案及证据引用。
3. 独立风控角色检查硬规则、数据质量、策略版本与草案摘要。
4. 店长查看完整证据并批准、拒绝或要求重新计算；参数/快照/政策改变会使旧审批失效。
5. 仿真服务核对摘要、权限、政策及库存前置条件后执行一次；冲突、超时或结果不确定时挂起并对账。
6. 审计记录最终状态；模拟反馈与历史观察分层呈现。

上述是需求状态语义，不表示现有 OpenDot Runtime 或 RetailOps 已实现本流程。
