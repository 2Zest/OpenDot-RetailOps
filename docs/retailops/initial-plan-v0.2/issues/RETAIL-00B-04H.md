## 1. 背景与目标
经营分析与独立风控需要角色隔离。本任务独立交付其职责，不承担下游模块实现。

## 2. 范围与明确不做
只调查 Goal Team/Handoff 的委派、回执、失败与权限；不部署云。不得修改未声明的模块、依赖版本、通用安全策略、既有断言；不连接真实商超写接口。调查任务不提前实现业务源码。

## 3. 输入
原版 goal-team-runtime、相关测试。实际启动时冻结上游 PR/commit、契约版本及证据路径；输入缺失或变更则停止并报告。

## 4. 输出
Handoff 接口及本地可行性说明。

## 5. 环境与前置条件
只读源码、隔离 fixture 测试。基线 WSL2 Ubuntu 24.04 / Node 24 / 原锁文件；执行前检查 git status、HEAD、用户授权、依赖验收。涉及真实模型/副作用只在批准的隔离实例执行。

## 6. 依赖与上下游
- 硬依赖：无新增任务硬依赖；仍需总体计划获批。
- 直接下游：RETAIL-00C、RETAIL-00B-04V。
- 依赖仅在对应契约/证据通过且 PR 已合并（或经批准的只读调查输入固定）后满足；BLOCKED、NOT_RUN 不视为满足。静态调查可记录负结论，但不得因此放行依赖实际运行能力的任务。

## 7. 实施步骤（初始）
1. 追踪委派/lease/恢复。节点验收：状态和身份。
2. 核对接收者工具范围。节点验收：只读权限证据。
3. 决定可验证本地候选。节点验收：运行计划。

每一步完成后执行总体计划的三方语义对齐（PRD/总体计划、Issue/Plan、节点标准），偏差修复并复测；不得跨过未通过节点。详见 `plans/RETAIL-00B-04H-PLAN.md`。

- T01：既有 goal-team 定向测试；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- T02：失败/uncertain 不得完成；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
