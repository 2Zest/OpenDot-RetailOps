# RETAIL-02 | 公开历史数据导入

状态：PROPOSED（未创建远程 Issue，未认领）｜阶段：V0｜责任角色：数据｜类型：工程/业务增量

## 1. 背景与目标
历史销售与仿真数据需分离。本任务独立交付其职责，不承担下游模块实现。

## 2. 范围与明确不做
仅实现可重复导入和查询历史数据；不做预测。不得修改未声明的模块、依赖版本、通用安全策略、既有断言；不连接真实商超写接口。调查任务不提前实现业务源码。

## 3. 输入
00E-02 manifest、01P。实际启动时冻结上游 PR/commit、契约版本及证据路径；输入缺失或变更则停止并报告。

## 4. 输出
导入器、数据 manifest、查询 repository。

## 5. 环境与前置条件
公开样本与临时 DB；大文件不入 Git。基线 WSL2 Ubuntu 24.04 / Node 24 / 原锁文件；执行前检查 git status、HEAD、用户授权、依赖验收。涉及真实模型/副作用只在批准的隔离实例执行。

## 6. 依赖与上下游
- 硬依赖：RETAIL-01P、RETAIL-00E-02。
- 直接下游：RETAIL-05F、RETAIL-04、RETAIL-03M、RETAIL-14。
- 依赖仅在对应契约/证据通过且 PR 已合并（或经批准的只读调查输入固定）后满足；BLOCKED、NOT_RUN 不视为满足。静态调查可记录负结论，但不得因此放行依赖实际运行能力的任务。

## 7. 实施步骤（初始）
1. 实现原始映射。节点验收：来源及单位保留。
2. 校验导入。节点验收：无重复、异常行报告。
3. 查询抽样。节点验收：与原数据比对。

每一步完成后执行总体计划的三方语义对齐（PRD/总体计划、Issue/Plan、节点标准），偏差修复并复测；不得跨过未通过节点。详见 `plans/RETAIL-02-PLAN.md`。

## 8. 测试用例
- T01：重复导入、缺字段、日期越界、空值、归一化单位；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- T02：原始哈希；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- 文档/工程回归：`git diff --check`、`npm run docs:check`；涉及源码时执行实际存在的类型检查及相关定向测试，记录命令、退出码和基线失败。测试位置和准确命令在认领时依据实际源码细化，不假定当前存在零售测试文件。

## 9. 验收标准
单店历史数据可复现查询，来源清楚；不转换成真实数量或金额。所有必需节点 PASS、实际证据可复核、未验证与阻塞如实标明、无越界修改，Review 通过并合并才 DONE；调查结论通过不等于被调查能力运行通过。

## 10. 交付物、PR 与回滚
- 本任务输出：导入器、数据 manifest、查询 repository。
- `acceptance/RETAIL-02.md` 或调查报告，记录节点回执、测试、实际 SHA、范围差异及限制；对应 Issue/Plan 版本与 PR。
- 单独分支 `feat/retail-02`（权限修复用 fix/），目标 `develop/retailops`，由用户确认后合并。共享 DB 迁移、路由注册、依赖等文件必须先协调，禁止并行改同一文件。
- 回滚：独立 revert；涉及 DB 保留备份及向前修复/兼容方案，不直接删除已有数据。禁止强推、reset --hard、git clean。
