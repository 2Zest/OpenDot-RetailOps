# RETAIL-18C | 单店双渠道库存预占

状态：PROPOSED（未创建远程 Issue，未认领）｜阶段：V1｜责任角色：库存｜类型：工程/业务增量

## 1. 背景与目标
同店线上订单与线下 POS 共享库存。本任务独立交付其职责，不承担下游模块实现。

## 2. 范围与明确不做
仅实现模拟线上预占/完成/取消及线下销售共享库存；不做商城、支付、配送。不得修改未声明的模块、依赖版本、通用安全策略、既有断言；不连接真实商超写接口。调查任务不提前实现业务源码。

## 3. 输入
03M 多 SKU fixture、01/01P 领域合同。实际启动时冻结上游 PR/commit、契约版本及证据路径；输入缺失或变更则停止并报告。

## 4. 输出
库存预占接口、订单事件及事务测试。

## 5. 环境与前置条件
临时 SQLite、模拟事件，禁止真实外部写入。基线 WSL2 Ubuntu 24.04 / Node 24 / 原锁文件；执行前检查 git status、HEAD、用户授权、依赖验收。涉及真实模型/副作用只在批准的隔离实例执行。

## 6. 依赖与上下游
- 硬依赖：RETAIL-03M。
- 直接下游：RETAIL-13B。
- 依赖仅在对应契约/证据通过且 PR 已合并（或经批准的只读调查输入固定）后满足；BLOCKED、NOT_RUN 不视为满足。静态调查可记录负结论，但不得因此放行依赖实际运行能力的任务。

## 7. 实施步骤（初始）
1. 定义可售=在手减预占。节点验收：状态与单位。
2. 实现预占/完成/取消及 POS 售出。节点验收：库存守恒。
3. 验证竞态及重复事件。节点验收：事务回执。

每一步完成后执行总体计划的三方语义对齐（PRD/总体计划、Issue/Plan、节点标准），偏差修复并复测；不得跨过未通过节点。详见 `plans/RETAIL-18C-PLAN.md`。
