# RETAIL-00B-03V | MCP exact-call 授权独立验证

状态：PROPOSED（未创建远程 Issue，未认领）｜阶段：P｜责任角色：安全｜类型：调查/准备，仅文档为默认

## 1. 背景与目标
真实外部 MCP 与审批未运行。本任务独立交付其职责，不承担下游模块实现。

## 2. 范围与明确不做
仅对本地无害测试 MCP 验证 consent、授权、调用及拒绝；不接真实业务。不得修改未声明的模块、依赖版本、通用安全策略、既有断言；不连接真实商超写接口。调查任务不提前实现业务源码。

## 3. 输入
00B-03 矩阵、00F。实际启动时冻结上游 PR/commit、契约版本及证据路径；输入缺失或变更则停止并报告。

## 4. 输出
真实 MCP receipt、权限及审批测试报告。

## 5. 环境与前置条件
独立测试 MCP server；无生产数据；固定工具 schema。基线 WSL2 Ubuntu 24.04 / Node 24 / 原锁文件；执行前检查 git status、HEAD、用户授权、依赖验收。涉及真实模型/副作用只在批准的隔离实例执行。

## 6. 依赖与上下游
- 硬依赖：RETAIL-00F、RETAIL-00B-03。
- 直接下游：RETAIL-04、RETAIL-09。
- 依赖仅在对应契约/证据通过且 PR 已合并（或经批准的只读调查输入固定）后满足；BLOCKED、NOT_RUN 不视为满足。静态调查可记录负结论，但不得因此放行依赖实际运行能力的任务。

## 7. 实施步骤（初始）
1. 注册只读和无害写 fixture。节点验收：目录/授权。
2. 调用并审批拒绝/同意。节点验收：实际 receipt。
3. 改参/撤销/重复。节点验收：拒绝。
4. 核对允许的读路径。节点验收：明确是否需人工批准。

每一步完成后执行总体计划的三方语义对齐（PRD/总体计划、Issue/Plan、节点标准），偏差修复并复测；不得跨过未通过节点。详见 `plans/RETAIL-00B-03V-PLAN.md`。

## 8. 测试用例
- T01：未 consent、改参、重复 request、撤销、拒绝、批准；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- T02：无权限副作用；保留实际输入、预期、结果、证据、退出码（不适用须说明）。
- 文档/工程回归：`git diff --check`、`npm run docs:check`；涉及源码时执行实际存在的类型检查及相关定向测试，记录命令、退出码和基线失败。测试位置和准确命令在认领时依据实际源码细化，不假定当前存在零售测试文件。

## 9. 验收标准
真实工具授权路径及可用运行模式确认；不默认所有只读自动执行；无安全路径则 BLOCKED。所有必需节点 PASS、实际证据可复核、未验证与阻塞如实标明、无越界修改，Review 通过并合并才 DONE；调查结论通过不等于被调查能力运行通过。
