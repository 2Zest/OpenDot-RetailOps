## N4 必须决定的业务/架构原则

用户已批准下列原则，不代表已冻结具体参数或完成相关能力的运行验收：

- 项目以 AI/Agent 工程能力为目标；单店经营只是受限场景，V0 保持单 SKU/单临期批次，V1 才评估扩展。
- 分析 Agent 必须是真实模型驱动的动态 Tool-use Loop；固定顺序脚本不算 Agent。只允许授权只读工具；缺证据须拒绝/补充。
- 经营分析与独立风控职责分离；LLM 语义风险分析与确定性硬规则分工；店长业务审批不可被工具调用授权替代。
- Memory 不作库存/政策/审批权威源；数据来源分层；所有真实业务写入不在当前范围。
- 状态安全 fail-closed：拒绝、撤销、超时、草案失效、uncertain 均不得自动流入执行/完成；uncertain 必须对账。
- 复用既有 OpenDot/Pi Runtime，不新增第二套 Agent Runtime；RETAIL-00F（GitHub Issue #7）安全验证与 Durable/MCP/Handoff 运行门槛保持有效。
- RETAIL-06（GitHub Issue #27）保留最小双情景真实模型行为验收；完整经营对照仍由 RETAIL-19（GitHub Issue #39）执行。一般指标阈值暂不视作已测结果。
- 硬规则违规、未授权写入、审批绕过及重复业务副作用为零容忍安全门槛，不是可以延期、调宽或与普通效果指标折抵的候选阈值。
